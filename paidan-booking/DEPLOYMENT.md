# 手动安装说明书：没有 AI Agent 也能使用

本说明适用于**第一次安装全新实例**，不要求会写代码，也不要求安装 AI 或注册 GitHub。需要在电脑上按步骤执行命令、编辑一处配置。已有订单的旧实例请先看下方「保存与升级」，不要重新创建存储。

这里用仓库自带的 Cloudflare 部署配置完成安装。部署后获得一个网页地址，客人可以从手机或电脑打开；自动排单和内置通知运行在服务端，你的电脑可以关闭。其他服务器也能适配，但不是照抄本说明即可完成。

## 1. 准备工具和账号

- 一台能安装 Node.js 并使用终端的电脑。
- 从 [Node.js 官网](https://nodejs.org/) 安装当前 LTS 版本，安装后重新打开终端。
- 注册并登录自己的 [Cloudflare 账号](https://dash.cloudflare.com/)。本说明使用其网页、后端与存储服务，额度和费用以平台规则为准。
- 暂时不用准备 AI API Key。通知服务的账号或凭据可以等预约功能跑通后再配置。

在终端逐条执行以下命令，能显示版本号说明工具已安装：

```sh
node --version
npm --version
```

Windows 可以使用 PowerShell 或命令提示符，macOS/Linux 使用终端。如果 PowerShell 提示禁止运行 `npm.ps1` 或 `npx.ps1`，可使用 `npm.cmd`、`npx.cmd` 执行相同命令，无需为此关闭系统安全策略。Wrangler 的系统要求见 [官方安装说明](https://developers.cloudflare.com/workers/wrangler/install-and-update/)。

## 2. 下载并进入项目目录

打开 [项目仓库](https://github.com/birdisleeee/photo-tools)，选择绿色的 **Code → Download ZIP**，完整解压。进入其中的 `paidan-booking` 文件夹，在该文件夹打开终端。

如果已经安装 Git，也可以执行：

```sh
git clone https://github.com/birdisleeee/photo-tools.git
cd photo-tools/paidan-booking
```

后续命令都在 `paidan-booking` 目录执行。确认这里能看到 `wrangler.jsonc`、`worker.js`、`backend.js`、`watch-runtime.js`、`index.html` 和 `admin.html`。不要只下载两个 HTML 文件。

## 3. 登录部署账号

```sh
npx wrangler@4 login
npx wrangler@4 whoami
```

首次运行时，按提示允许安装 Wrangler。浏览器打开授权页面后，登录你自己的账号并授权；第二条命令用于核对当前账号。这里不需要 `npm start`，也不需要重新生成一个空项目。

## 4. 创建自己的空白存储

```sh
npx wrangler@4 kv namespace create PAIDAN_KV
```

命令成功后会给出新命名空间的 `id`。用文本编辑器打开 `wrangler.jsonc`，只把 `REPLACE_WITH_YOUR_NAMESPACE_ID` 替换成刚才得到的 ID，并保存。例如下面只是结构示意，不能原样使用占位文字：

```json
"kv_namespaces": [
  { "binding": "PAIDAN_KV", "id": "替换成命令返回的真实ID" }
]
```

这个存储用于空实例初始化及兼容读取。配置中的 `BOOKING_STORE` 和迁移声明会在部署时建立本项目需要的持久化对象，保留原样；不要复制作者或其他项目的存储 ID。KV 命令及绑定说明见 [官方文档](https://developers.cloudflare.com/kv/get-started/)。

`name` 默认是 `photo-booking`。如果你的账号下已有同名项目，请在首次部署前换成另一个未使用的小写英文、数字与连字符组成的名称，避免覆盖。首次安装后不要随意改名或更换绑定。

## 5. 部署并设置管理员密钥

先部署项目：

```sh
npx wrangler@4 deploy
```

按终端提示完成账号选择及必要的子域名设置，保存部署结果中的网页地址。首次部署时还没设置管理密钥，页面提示 `Service not configured` 是预期状态，继续下一步。

用密码管理器生成并保存一个至少 32 位的随机字母数字串，作为自己的后台密钥。然后执行：

```sh
npx wrangler@4 secret put ADMIN_KEY
```

在命令提示输入值时粘贴密钥，不要把实际密钥写进命令、`wrangler.jsonc` 或 GitHub。等待上传成功，再打开网页。这条命令会更新线上秘密配置；详见 [官方 Secrets 说明](https://developers.cloudflare.com/workers/configuration/secrets/)。

两种链接用途不同：

| 链接 | 给谁使用 |
| --- | --- |
| 部署结果中的根网址 | 给客人预约，例如 `https://你的项目.你的子域.workers.dev/` |
| 同一网址加 `/admin?key=你保存的管理员密钥` | 仅摄影师自己管理，不要分享给客人 |

默认部署地址可用后，也可以自行绑定域名。先完成下面的首次设置，再分享预约链接。

## 6. 创建并发布第一届

1. 用管理链接进入后台。此时应没有任何作者的届次、订单或历史存档。
2. 点击「新开一届」，填写名称、拍摄日期、开始/结束时间、每单时长及正常单价。
3. 填写客人看到的页面说明、拍摄须知、备注提示、联系方式和付款说明。
4. 查看客人页面预览，点击「预览并确认」，核对后发布。
5. 用另一个浏览器窗口打开根网址，确认名称、日期、可用时段和联系方式是你自己的，再把根网址分享给客人。

未发布第一届时，客人页面显示“预约暂未开放”是正常的。之后可在后台管理预约和收款，结束后归档；新开一届时预约链接不用更换。

## 7. 按需开启通知

通知不是使用预约功能的前提，可以暂时关闭。

需要提醒时，在后台「设置 → 脚本值守」选择通用 Webhook、企业微信、飞书、Telegram 或邮件，填写自己的配置，勾选事件并确认保存。随后点击「测试已保存渠道」，再次确认，检查目标群聊或邮箱是否实际收到。

邮件需要 Resend 的 API Key、已验证域名下的发件地址和收件邮箱；不是填写邮箱登录密码。其他渠道及字段说明见 [值守与邮件配置](./WATCHER.md)。内置通知不需要额外 Cron，不需要自己的 Agent 或常驻电脑。

## 8. 检查是否安装成功

- 后台能进入，初始数据为空，发布后客人页面显示自己的内容。
- 在自己选择的测试时段，用自己的信息提交一笔测试预约；后台应看到订单，该时段不可再被预约。
- 用订单号或自己的手机号查询，取消这笔测试预约，确认后台显示取消且时段释放。测试取消记录会留在全部订单中，不要把它误认为作者附带的数据。
- 在手机浏览器检查预约页和后台菜单。
- 如果开启通知，检查对应测试消息实际收到；只看到接口成功提示不等于收件端已收到。未开通知时，预约仍能正常使用。

## 常见问题

| 遇到的情况 | 检查方式 |
| --- | --- |
| `node` / `npx` 找不到 | 确认已安装 Node.js，重开终端，并检查版本命令 |
| 找不到配置或入口文件 | 确认终端位于含 `wrangler.jsonc` 的 `paidan-booking` 文件夹 |
| 部署提示命名空间或权限错误 | 检查占位 ID 是否替换，`whoami` 是否为创建存储的账号；按平台报错核查权限 |
| `Service not configured` | 在同一项目目录执行 `secret put ADMIN_KEY`，确认上传成功后刷新 |
| 后台显示 `unauthorized` | 检查链接中的 key 是否与自己设置的密钥一致，不要使用文档占位值 |
| 前台显示预约暂未开放 | 先在后台创建并确认发布第一届 |
| 双击 HTML、GitHub Pages 只有界面或无法提交 | 它们没有运行本项目后端，请按上述步骤完整部署 |
| 没收到提醒 | 检查值守是否开启并保存、提醒事件是否勾选、渠道测试结果；邮件再查垃圾箱和发信日志 |

## 可选：只在本地试用

在 `paidan-booking` 目录创建不提交到 Git 的 `.dev.vars`，内容如下，将占位值换成自己的本地测试密钥：

```dotenv
ADMIN_KEY="替换为本地随机测试密钥"
```

执行 `npx wrangler@4 dev`，打开终端显示的本地网址，后台同样加 `/admin?key=本地测试密钥`。本地存储与线上独立，本地填写的内容不会随代码自动发布；本地服务关闭后便无法访问，这个地址不能直接发给远程客人。

## 保存与升级

所有 API 由同一个持久化协调对象处理。修改先暂存，成功后通过存储事务统一提交，避免同时预约抢占或编辑覆盖。旧 KV 数据按原键结构读取，新修改保存在持久化对象中；KV 并非新版数据的持续镜像。不要继续用旧脚本直接改 KV，也不要直接回退到只读取 KV 的旧版本。

从旧版本升级前，备份网页、接口代码、完整 KV 和附件，在独立环境演练。发布后核对各届订单数量、收款和附件。回退前必须导出新版持久化状态并恢复兼容数据结构；单独恢复旧网页或旧 KV 不能恢复升级后新增的记录。

新建实例从空白开始，不生成示例届、不附带历史存档或订单，也不预填日期、单价、设备或联系方式。管理员先设置并发布自己的第一届；发布前，客人页面显示“预约暂未开放”。请使用自己创建的全新存储资源。

## 运行约定

- 图片凭证只供管理员查看；不要将真实数据放进公开仓库。
- 手机号／订单号查询适合小范围预约链接。如面向开放公众使用，建议增加验证码、限流和更强的身份验证。
- 客人付款通知和管理员确认收款分开；本工具不负责资金流转。
- 客人停留在旧一届表单时，切届后的提交会被拒绝并提示刷新。
- 预览使用同源 iframe；自行添加安全响应头时需允许同源嵌入。
- 服务费用和限额以平台当前规则为准。
