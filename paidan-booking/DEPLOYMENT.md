# 部署示例

下面以 Cloudflare 为例。前台与后台使用同一域名，后台地址为 `/admin?key=你的管理员密钥`，请勿将管理链接发给客人。

1. 安装 Node.js，并在本目录执行 `npx wrangler login`。
2. 执行 `npx wrangler kv namespace create PAIDAN_KV`，把返回的 namespace ID 填入 wrangler.jsonc。该命名空间用于空实例初始化及旧版本兼容，不包含预置客人数据。
3. 执行 `npx wrangler secret put ADMIN_KEY`，输入自己生成的长随机密钥，不要写入 Git、截图或示例 URL。
4. 执行 `npx wrangler deploy`，使用返回的网址，或绑定自己的域名。
5. 进入后台，新开一届并填写自己的拍摄安排和联系方式，确认后分享前台链接。

本地运行可创建不提交到 Git 的 `.dev.vars`，填写 `ADMIN_KEY="仅用于本地的密钥"`，再执行 `npx wrangler dev`。本地存储与线上独立。

## 保存与升级

所有 API 由同一个持久化协调对象处理。修改先暂存，成功后通过存储事务统一提交，避免同时预约抢占或编辑覆盖。旧 KV 数据按原键结构读取，新修改保存在持久化对象中；KV 并非新版数据的持续镜像。不要继续用旧脚本直接改 KV，也不要直接回退到只读取 KV 的旧版本。

从旧版本升级前，备份网页、接口代码、完整 KV 和附件，在独立环境演练。发布后核对各届订单数量、收款和附件。回退前必须导出新版持久化状态并恢复兼容数据结构；单独恢复旧网页或旧 KV 不能恢复升级后新增的记录。

新建空实例会生成一个无订单的示例届，发布自己的第一届后自动归档示例届。

## 运行约定

- 图片凭证只供管理员查看；不要将真实数据放进公开仓库。
- 手机号／订单号查询适合小范围预约链接。如面向开放公众使用，建议增加验证码、限流和更强的身份验证。
- 客人付款通知和管理员确认收款分开；本工具不负责资金流转。
- 客人停留在旧一届表单时，切届后的提交会被拒绝并提示刷新。
- 预览使用同源 iframe；自行添加安全响应头时需允许同源嵌入。
- 服务费用和限额以平台当前规则为准。
